# Agent Guidelines for RESMAP

This repository contains a full-stack application with a React frontend and a Python backend.

## Project Structure
- `frontend/`: React + TypeScript + Vite
- `backend/`: Python (Project structure evolving)

## 1. Build, Lint, and Test Commands

### Frontend (`frontend/`)
- **Development Server**: `npm run dev`
- **Build**: `npm run build`
- **Preview Build**: `npm run preview`
- **Install Dependencies**: `npm install`
- **Testing**:
  - No test runner is currently configured.
  - **Agent Action**: If asked to write tests, please set up **Vitest** and add a `"test": "vitest"` script to `package.json`.
  - **Running Single Test**: `npm run test -- <path/to/file>` (once configured).
- **Linting**:
  - No explicit lint script in `package.json`.
  - **Agent Action**: Assume ESLint is used. Follow standard React/TypeScript linting rules.

### Backend (`backend/`)
- **Runtime**: Python 3.12+
- **Dependency Management**: Uses **`uv`**. `pyproject.toml` is the source of truth.
- **Setup**: `uv sync` to install dependencies.
- **Run**: `uv run uvicorn app.main:app --reload`
- **Testing**:
  - **Agent Action**: Use `uv run pytest`.
  - **Running Single Test**: `uv run pytest <path/to/test_file.py>`
- **Linting**:
  - **Agent Action**: Use `ruff` or `flake8` via `uv run`.

## 2. Code Style & Conventions

### General
- **Formatting**:
  - **Frontend**: 2 spaces indentation. Semicolons required.
  - **Backend**: 4 spaces indentation (PEP 8).
- **File Naming**:
  - React Components: `PascalCase.tsx` (e.g., `HeroSection.tsx`).
  - Python Modules: `snake_case.py`.
- **Comments**:
  - Use comments to explain *why* logic exists, not *what* it does.
  - Use JSDoc for complex frontend functions and Docstrings for Python functions.

### Frontend (React/TypeScript)
- **Imports**:
  - Group imports: React/Library imports -> Components -> Data/Utils -> Types.
  - Use absolute imports (`@/`) if configured (currently `@/*` maps to `./src/*`).
- **Components**:
  - Use Functional Components with `React.FC` or direct function declarations.
  - Use Hooks (`useState`, `useEffect`) at the top level of components.
- **Styling**:
  - Use **Tailwind CSS** classes directly in `className`.
  - Group related Tailwind classes logically (layout -> spacing -> typography -> colors).
- **Types**:
  - Define interfaces/types in `src/types.ts` or co-located if specific to a component.
  - Avoid `any`. Use strict typing.
- **Error Handling**:
  - Use Error Boundaries for UI crashes.
  - Handle async errors with try-catch blocks.

### Backend (Python)
- **Style**:
  - Follow **PEP 8**.
  - Use Type Hints (`def my_func(a: int) -> str:`) extensively.
- **Structure**:
  - Keep `main.py` clean. Move logic to separate modules/packages as the project grows.
- **Error Handling**:
  - Use specific exceptions (e.g., `ValueError` instead of generic `Exception`).

## 3. Rules & Instructions

### Creating New Features
1. **Frontend**:
   - Create new components in `src/components/`.
   - If the component is a specific "Step" in the wizard, place it in `src/components/steps/`.
   - Update `src/data/` if adding new static content.
2. **Backend**:
   - Ensure `pyproject.toml` is updated if adding dependencies.

### Refactoring
- When refactoring `App.tsx` or main layouts, ensure `SidebarDots` and `Navigation` logic remains consistent with the section structure.
- Maintain the "Step" architecture for the wizard flow.
